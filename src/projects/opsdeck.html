A personal dashboard for the pull requests that need me.

In brief

Purpose
A personal pull request dashboard.
Access
Private, runs locally.
Stack
Go, SQLite, net/http, GitHub GraphQL, gh CLI, vanilla JavaScript, Datadog, Sentry.

How it works

opsdeck is a local-first dashboard that an engineer runs on their own machine against their own gh login. It gathers every pull request they are connected to and sorts them into four bays: review requested of me, review requested of my team, authored or pushed, and commented or reviewed. Anything waiting on the user, such as a review request, red CI or a merge conflict, comes first. It is keyboard-driven (j/k, h/l, Space to lift a PR). Sending selected PRs to Claude Code review skills is designed into the UI, but in the current build that dispatch is simulated.

Work and personal organisations live in separate spaces, each with its own SQLite database and bot list. opsdeck also finds PRs opened by the user’s GitHub App bots and by local Claude Code sessions, so PRs a login-only query would miss still appear. The metrics view covers merged PRs per week, cycle time at p50 and p90, first-pass yield, revert rate, review response time and review-queue age. Every figure shows its sample size and flags thin samples. An optional production view links Datadog and Sentry deploys to the commits they ship, for deploy frequency, batch size and merge-to-production lead time.

It ships as a single Go binary with no runtime dependencies. opsdeck serve binds to loopback only, serves an embedded static UI and a JSON snapshot API, and runs its own scheduler with 60-second and 15-minute ticks. It uses a pure-Go SQLite driver, so no CGO is needed. The screenshots below use invented demo data.
